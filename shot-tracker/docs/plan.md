# 籃球投籃軌跡分析：專案規劃

## 目標

透過分析投籃軌跡，找出**失手的原因**（弧度太平、太短、太長、不穩定），並追蹤練習中的改善，進而提高命中率。
主要給自己練習用，保留之後上架的可能性。

## 已確定的決定

| 項目 | 決定 | 原因 |
|---|---|---|
| 使用情境 | 個人練投，手機固定在場邊 | 籃框位置固定，分析比較簡單 |
| 手機 | iPhone | 使用者的手機 |
| 開發環境 | Windows（沒有 Mac） | 不能用 Xcode → 不做原生 iOS |
| App 形式 | **PWA 網頁 App**，在 iPhone Safari 上執行 | 可以在 Windows 開發、直接用 iPhone 測試，也符合使用者會的網頁前端 |
| 分析引擎 | Python | 使用者熟悉；Phase 0 的程式碼之後可以直接當後端 |
| 伺服器 | 先用使用者自己的電腦（同一個 Wi-Fi） | 免費；雲端之後再討論 |
| 拍攝角度 | 側面 | 看得到弧度、入框角度、前後深度 |
| 籃框位置 | 使用者手動點選 | 比訓練籃框偵測模型簡單，也更準 |

## 階段

### Phase 0：Python 原型 ✅ 進行中
- [x] 合成測試影片（有標準答案）
- [x] 籃球偵測（顏色 + 移動）、追蹤
- [x] 拋物線擬合、出手點偵測
- [x] 指標：出手角度/速度/高度、最高點、入框角度、深度
- [x] 進球判定 + 失手分類（偏短／偏長／其他）
- [x] 輸出：標註影片、軌跡疊圖、CSV/JSON、中文建議
- [x] 用公開的真實影片驗證：3 段影片、11 球的進／不進全部正確
- [x] 多目標追蹤（真實畫面裡有很多和球顏色接近的東西）
- [x] 用重力自動偵測影片速度（加速影片、慢動作匯出）
- [ ] **用使用者自己拍的正側面影片驗證角度與深度的準確度** ← 等使用者提供影片
- [ ] 必要時改用 YOLO 或自己訓練的偵測模型

### Phase 1：網頁上傳分析
- Python 後端（FastAPI）包裝 Phase 0 的分析流程
- 網頁前端：在 iPhone 上選擇影片 → 點籃框 → 上傳 → 顯示結果
- 用 iPhone 內建相機拍慢動作（120/240fps），數據最精確

### Phase 2：PWA 即時模式
- 在瀏覽器裡開相機（getUserMedia），用輕量模型在手機上即時偵測
- 即時顯示軌跡、語音回報「進／不進、弧度」
- 限制：Safari 的相機影格率通常是 30fps，所以精確數據還是以 Phase 1 為主

### Phase 3：練習紀錄
- 歷史紀錄、趨勢圖、進球和失手的指標比較
- 姿勢分析（MediaPipe Pose）：出手點、手肘角度、出手時間

### Phase 4（選擇性）：上架
- 用雲端編譯（Expo EAS Build / Codemagic）產生 iOS App，不需要 Mac
- 需要 Apple Developer Program（US$99/年）
- 偵測模型要避開 AGPL 授權（Ultralytics YOLO）：改用自己訓練、授權寬鬆的模型

## 主要風險

| 風險 | 對策 |
|---|---|
| 真實場地光線差，顏色偵測不準 | 改用 YOLO，再用自己的影片微調 |
| 側面拍攝看不到左右偏差 | 用球網晃動輔助判定；或用第二支手機從後方拍 |
| Safari 即時效能不足 | 降低解析度、使用輕量模型、即時模式只提供基本回饋 |
